# Numera Browser dashboard

The browser console is implemented in Rust and compiled to WebAssembly. It uses
the original theme tokens, scoped CSS and public image assets. Application state,
rendering, DOM events, authenticated requests and desktop bridges live in `rust/`.
The JavaScript in `dist/assets/` is generated by wasm-bindgen.

Build from the repository root with Rust, the WebAssembly target and the matching
wasm-bindgen CLI:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked
cargo run --locked --manifest-path dashboard/Cargo.toml --bin dashboard-build
```

The build stages its output before replacing `dist/`. It emits `index.html`,
`assets/numera_dashboard.js`, `assets/numera_dashboard_bg.wasm`, the stylesheet and
public images. `ci-source.json` records the source revision, version and runtime.
The native engine serves this directory at its own origin. A portable desktop
package uses the same files under `web/`.

For development, run the native engine with `numera serve`, then:

```sh
cargo run --locked --manifest-path dashboard/Cargo.toml --bin dashboard-dev
```

The development server listens on `127.0.0.1:5173` and forwards `/api/` to
`127.0.0.1:8787`. Production requests use their own origin, including the desktop
shell's dynamically selected port. An explicit `NUMERA_API_URL` environment
variable at build time can override the API location.

When the engine is offline the console shows clearly labelled sample profiles in
memory. A reachable engine that requires authentication shows the token screen.
Saving a stale profile retains the draft, rebases independent edits and asks for
explicit resolution of overlapping fields. Password controls distinguish retaining,
replacing, clearing and removing a proxy credential. Conflict previews hide secrets.
Software updates and Cloak downloads each require approval of the exact reviewed
target; browser launches never grant download consent.

The original 195-case inventory is retained in
[`tests/vitest-case-inventory.json`](tests/vitest-case-inventory.json), with the
original suite, case description, parameters, source hash, test kind and Rust test
ID. The 71 ordinary unit cases run natively. The 123 component cases and one
platform timezone case run inside Chromium with actual DOM events and Rust HTTP
fixtures. Together they cover the same 26 suites with no ignored cases.

```sh
cargo test --locked --manifest-path dashboard/Cargo.toml --all-targets
cargo clippy --locked --manifest-path dashboard/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path dashboard/Cargo.toml --check

# Chrome/Chromium and a matching chromedriver must be available.
CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER=wasm-bindgen-test-runner \
WASM_BINDGEN_TEST_WEBDRIVER_JSON=dashboard/tests/webdriver.json \
cargo test --locked --manifest-path dashboard/Cargo.toml --lib --target wasm32-unknown-unknown
```

Set `CHROMEDRIVER` to the driver path when it is not on `PATH`. On machines where
Chromium has a nonstandard executable path, supply a local WebDriver capability
file with `goog:chromeOptions.binary`. Browser fixtures use Rust closures and real
`Response`, `Blob`, `File`, `AbortSignal` and DOM objects; they require no Python,
Node, npm or browser automation application runtime.
